## 📋 Overview

`THIRTY3/daily/` is the central repository for tracking daily learning progress across **4 cybersecurity phases** (Beginner → OSCP). This directory is the source of truth for:

- **Daily learning logs** — Time-tracked activities, concepts mastered, CTF challenges
- **Weekly progress reports** — Auto-generated by Learning Tracker subagent
- **Learning phase management** — Track current phase, estimated completion, next milestones
- **OSINT investigation linking** — Daily notes link to active investigations

## 📝 File Format

Each daily note follows this pattern:

**Filename:** `YYYY-MM-DD_learning_progress.md`

**Example:** `2026-02-20_learning_progress.md`

**YAML Frontmatter:**
```yaml
---
date: 2026-02-20
type: learning-progress
phase: [2]
tags: [learning, phase-2, ctf, osint, exploitation]
status: active
source: REPORT/Février
---
```

**Content Structure:**
See `TEMPLATE_DAILY.md` for the full template with sections for:
- Phase current (Phase number, focus, time logged)
- Today's activities (Challenges, concepts, OSINT investigations)
- Concepts mastered (Learning achievements)
- Blockers (Obstacles encountered)
- Progress against phase (Goals completion percentage)
- Links created (References to OSINT investigations and resources)
- Next session goals (3 priorities for next session)

## 🔗 Integration with Learning Tracker

The **Learning Tracker subagent** reads this directory automatically:

**Schedule:** Every Tuesday at 19:00 EST (or manual trigger: `/progress-check`)

**Data Sources:**
- All files in `THIRTY3/daily/2026/MM/` (last 7 days)
- YAML frontmatter (date, phase, tags, status)
- File content (activities, concepts, blockers)

**Outputs:**
- `_BRAIN/WEEKLY_HACKING_PROGRESS.md` (human-readable weekly report)
- `THIRTY3/daily/INDEX_DAILY.md` (updated progress dashboard)
- Weekly recommendations (adaptive based on progress and blockers)

**Configuration:** See `_config.yaml` for detailed settings

## ✅ Daily Workflow

### Morning (Session Start)
1. Create a new entry if not already made: `YYYY-MM-DD_learning_progress.md`
2. Or edit today's file if it already exists
3. Use `TEMPLATE_DAILY.md` as reference for structure

### During Session
1. Log activities as you complete them:
   - CTF challenges (platform, name, time, status)
   - Concepts learned (with brief explanations)
   - OSINT investigations (link to active investigation note)
   - Blockers encountered (description, attempted solutions)

2. Track time for each activity (helps calculate phase completion)

### End of Week (Thursday/Friday)
1. Review all 7 daily notes
2. Manual trigger: `/progress-check` (generates weekly report)
3. Review generated report in `_BRAIN/WEEKLY_HACKING_PROGRESS.md`
4. Plan next week's goals based on recommendations

## 📈 Metrics Tracked

Each daily note contributes to:
- **Time logged** — Total minutes spent on learning (cumulative per phase)
- **Challenges completed** — CTF challenges solved (platform, difficulty, time)
- **Concepts mastered** — New security concepts learned
- **Blockers** — Obstacles encountered and resolution attempts
- **Phase progress** — Estimated % completion toward current phase target

The Learning Tracker subagent aggregates these into:
- Weekly summary (time, challenges, concepts)
- Phase progress (X% of target hours completed)
- Estimated completion date for current phase
- Adaptive recommendations for next week

## 🔄 Weekly Automation

**Every Tuesday at 19:00 EST:**
1. Learning Tracker reads all daily notes (last 7 days)
2. Extracts metrics (time, challenges, concepts, blockers)
3. Cross-references RESSOURCES_LEARNING.md for phase info
4. Generates weekly report → `_BRAIN/WEEKLY_HACKING_PROGRESS.md`
5. Updates INDEX_DAILY.md with latest metrics
6. Provides adaptive recommendations for next week

**Manual Trigger:**
```
/progress-check
```
Generates same weekly report on demand.
