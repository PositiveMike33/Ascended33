# Aperçu des applications Discord[](https://discord.com/developers/docs/quick-start/overview-of-apps#overview-of-discord-apps)

![Aperçu des applications](https://discord.com/assets/88ed13de529b42c4.webp)

Les applications Discord personnalisent, étendent et améliorent Discord pour des millions d'utilisateurs. Que vous soyez un développeur intéressé par la création d'une activité, la personnalisation de serveurs ou l'intégration d'un jeu, les applications sont le conteneur qui vous permet de donner vie à votre idée.

Sur cette page, nous répondrons aux questions suivantes :

- [Que peuvent faire les applications ?](https://discord.com/developers/docs/quick-start/overview-of-apps#what-can-apps-do)
- [Où les applications sont-elles installées ?](https://discord.com/developers/docs/quick-start/overview-of-apps#where-are-apps-installed)
- [Quelles API les applications peuvent-elles utiliser ?](https://discord.com/developers/docs/quick-start/overview-of-apps#what-apis-can-apps-use)

---

## Que peuvent faire les applications ?

](https://discord.com/developers/docs/quick-start/overview-of-apps#what-can-apps-do)

Vous découvrirez toutes les possibilités des applications au fur et à mesure que vous explorerez la documentation et que vous commencerez à construire, mais pour l'instant, jetons un coup d'œil sur certaines fonctionnalités que vous pouvez construire et intégrer pendant que vous développez votre application.

### Envoyer et gérer des messages[

](https://discord.com/developers/docs/quick-start/overview-of-apps#send-and-manage-messages)

Les messages font partie intégrante de Discord, et c'est également le cas pour les applications. Les applications peuvent envoyer des messages de plusieurs manières : elles peuvent appeler le point de terminaison [Créer un message](https://discord.com/developers/docs/resources/message#create-message), créer et exécuter des [webhooks](https://discord.com/developers/docs/resources/webhook), ou répondre avec un message lorsqu'elles répondent à une [interaction](https://discord.com/developers/docs/interactions/overview). Les applications peuvent également gérer les messages si elles disposent des autorisations nécessaires, ce qui est expliqué plus en détail dans la [documentation sur les messages] (https://discord.com/developers/docs/resources/message).

### Interagir avec les utilisateurs[

](https://discord.com/developers/docs/quick-start/overview-of-apps#interact-with-users)

Les applications peuvent utiliser les [interactions](https://discord.com/developers/docs/interactions/overview) pour créer des expériences plus attrayantes et plus intuitives pour les utilisateurs. Lors de l'envoi de messages, les applications peuvent envoyer des composants interactifs tels que des [boutons](https://discord.com/developers/docs/components/reference#button) et des [menus de sélection](https://discord.com/developers/docs/components/reference#string-select) dans le champ `composants`. Les applications peuvent également ouvrir des formulaires modaux ou lancer une activité [en réponse à des interactions] (https://discord.com/developers/docs/interactions/receiving-and-responding#interaction-response-object-modal).

### Créez des jeux et des expériences intégrés[

(https://discord.com/developers/docs/quick-start/overview-of-apps#build-embedded-games-and-experiences)

En utilisant le [Embedded App SDK](https://discord.com/developers/docs/developer-tools/embedded-app-sdk), les applications peuvent créer des [Activities](https://discord.com/developers/docs/activities/overview) qui sont des jeux interactifs multiplateformes et des expériences sociales dans Discord. Ils s'exécutent dans des iframes dans Discord, où les joueurs se retrouvent déjà.

### Personnaliser les serveurs[

](https://discord.com/developers/docs/quick-start/overview-of-apps#customize-servers)

Avec les bons points de terminaison API et les [permissions](https://discord.com/developers/docs/topics/permissions) appropriées, les applications peuvent personnaliser l'expérience d'utilisation et de modération des serveurs en accédant et en personnalisant toutes sortes de ressources essentielles à Discord, notamment [users](https://discord.com/developers/docs/resources/user), [channels](https://discord.com/developers/docs/resources/channel) et [AutoMod](https://discord.com/developers/docs/resources/auto-moderation), pour n'en citer que quelques-unes. Explorez la catégorie de documentation Ressources pour en savoir plus sur les différentes ressources Discord et sur la façon dont les applications peuvent les utiliser.

### Mise à jour des métadonnées utilisateur et de la présence[

](https://discord.com/developers/docs/quick-start/overview-of-apps#update-user-metadata-and-presence)

Les applications peuvent mettre à jour les métadonnées d'un utilisateur Discord avec les données d'un jeu ou d'une application de plusieurs façons. Les applications peuvent également mettre à jour le profil d'un utilisateur avec des données exploitables provenant d'un jeu ou d'une application en intégrant [Rich Presence](https://discord.com/developers/docs/rich-presence/overview). Les applications peuvent également utiliser [role connection metadata](https://discord.com/developers/docs/resources/application-role-connection-metadata) pour associer des métadonnées tierces (comme les statistiques ou le type de compte) aux utilisateurs de Discord, que les administrateurs de serveur peuvent utiliser pour définir des rôles. Vous pouvez en savoir plus dans le tutoriel [configurer les métadonnées pour les rôles liés](https://discord.com/developers/docs/tutorials/configuring-app-metadata-for-linked-roles).

### Ajouter des fonctionnalités premium[

](https://discord.com/developers/docs/quick-start/overview-of-apps#add-premium-features)

Les [abonnements aux applications](https://discord.com/developers/docs/monetization/implementing-app-subscriptions) permettent aux applications de faire payer les utilisateurs et/ou les serveurs pour des fonctionnalités premium sur une base récurrente, de manière native dans Discord. Vous pouvez en savoir plus sur l'éligibilité et l'ajout de fonctions de monétisation à votre application dans la documentation [Monetization](https://discord.com/developers/docs/monetization/overview).

### ...et plus[

](https://discord.com/developers/docs/quick-start/overview-of-apps#and-more)

Cette documentation destinée aux développeurs est pleine de coins et de recoins avec toutes sortes de fonctionnalités à explorer. Découvrez les possibilités en explorant davantage la documentation, ou en [créant votre propre application](https://discord.com/developers/applications).

## Où sont installées les applications ?

](https://discord.com/developers/docs/quick-start/overview-of-apps#where-are-apps-installed)

Les applications Discord peuvent être installées dans deux contextes différents :

1. Les applications installées sur un serveur (appelé [guild](https://discord.com/developers/docs/resources/guild) dans l'API) par un utilisateur disposant de l'autorisation Manage Server ([`MANAGE_GUILD`](https://discord.com/developers/docs/topics/permissions#permissions-bitwise-permission-flags)). Les applications installées sur un serveur ne peuvent être utilisées que sur ce serveur et dans les DM avec l'utilisateur bot de l'application, et sont visibles par tous les membres du serveur.
2. Applications installées sur un compte utilisateur. Les applications installées sur le compte d'un utilisateur ne sont visibles que par cet utilisateur, sur l'ensemble de ses serveurs, DM et DM de groupe par défaut.

Les contextes d'installation pris en charge par une application peuvent être limités par le développeur lors de la [configuration de l'application] (https://discord.com/developers/docs/resources/application#setting-supported-installation-contexts). Vous trouverez des détails sur les contextes d'installation dans la [documentation sur les ressources de l'application](https://discord.com/developers/docs/resources/application#installation-context).

## Quelles API les applications peuvent-elles utiliser ?[

](https://discord.com/developers/docs/quick-start/overview-of-apps#what-apis-can-apps-use)

Il existe une poignée d'API différentes que vous pouvez choisir en fonction de la fonctionnalité de votre application et des fonctions de Discord auxquelles vous souhaitez accéder. Vous trouverez ci-dessous un aperçu rapide des principales API de la plateforme de développement Discord, mais vous pouvez lire plus de détails et d'informations sur l'utilisation des API dans la [Référence API](https://discord.com/developers/docs/reference).

### HTTP API[

](https://discord.com/developers/docs/quick-start/overview-of-apps#http-api)

L'API HTTP est une API REST qui vous permet d'interagir et de modifier les ressources principales de Discord comme les [canaux](https://discord.com/developers/docs/resources/channel), les [serveurs (ou guildes)](https://discord.com/developers/docs/resources/guild), les [utilisateurs](https://discord.com/developers/docs/resources/user) et les [messages](https://discord.com/developers/docs/resources/message#message-object).

Utilisez l'API HTTP pour :

- récupérer des informations sur une ressource
- Créer, mettre à jour ou supprimer une ressource

Pour en savoir plus sur l'utilisation de l'API HTTP, consultez la [Référence API](https://discord.com/developers/docs/reference#http-api).

### Gateway API[

](https://discord.com/developers/docs/quick-start/overview-of-apps#gateway-api)

L'API Gateway vous permet de recevoir des données d'événement via une WebSocket à chaque fois qu'un [événement](https://discord.com/developers/docs/events/gateway-events) se produit sur un serveur où votre application est installée.

Utilisez l'API de passerelle pour :

- Recevoir des événements se produisant dans Discord

Lisez les détails sur l'utilisation de l'API de passerelle dans la [Référence API] (https://discord.com/developers/docs/reference#gateway-websocket-api).
