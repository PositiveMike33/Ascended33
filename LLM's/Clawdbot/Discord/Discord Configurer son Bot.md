Les [applications Discord] (https://discord.com/developers/docs/quick-start/overview-of-apps) vous permettent de personnaliser et d'étendre Discord à l'aide d'un ensemble d'API et de fonctionnalités interactives. Ce guide vous guidera dans la création de votre première application Discord à l'aide de JavaScript. À la fin, vous aurez une application qui utilise des commandes slash, envoie des messages et répond aux interactions des composants.

Si vous souhaitez créer un jeu ou une expérience sociale dans une iframe, vous pouvez suivre le tutoriel pour [créer une activité] (https://discord.com/developers/docs/activities/building-an-activity).

Nous allons créer une application Discord qui permet aux utilisateurs de jouer à pierre-papier-ciseaux (avec 7 choix au lieu de 3). Ce guide est destiné aux débutants, mais il suppose des connaissances de base en [JavaScript](https://developer.mozilla.org/en-US/docs/Learn/Getting_started_with_the_web/JavaScript_basics).

## Étape 0 : Configuration du projet
(https://discord.com/developers/docs/quick-start/getting-started#step-0-project-setup)

Avant de commencer, vous devez configurer votre environnement local et récupérer le code du projet depuis le [dépôt de l'application exemple](https://github.com/discord/discord-example-app).

Nous développerons notre application localement avec l'aide de [ngrok](https://ngrok.com/), mais vous pouvez utiliser l'environnement de développement de votre choix.

Si vous n'avez pas installé [NodeJS](https://nodejs.org/en/download/), installez-le d'abord.

Une fois NodeJS installé, ouvrez votre ligne de commande et clonez le code du projet :

Copiez

```
git clone https://github.com/discord/discord-example-app.git
```

Naviguez ensuite dans le répertoire et installez les dépendances du projet :

Copiez

```
# naviguez jusqu'au répertoire
cd discord-example-app

# installez les dépendances
npm install
```

Structure du projet

Vue d'ensemble de la structure du projet pour l'application exemple utilisée dans ce tutoriel

Ceci étant dit, ouvrez votre nouveau projet dans l'éditeur de code de votre choix, et nous allons passer à la mise en place de votre application Discord.

## Étape 1 : Création d'une application[

](https://discord.com/developers/docs/quick-start/getting-started#step-1-creating-an-app)

Tout d'abord, vous devez créer une application dans le portail des développeurs si vous n'en avez pas déjà une :

Créer une application

Saisissez un nom pour votre application, puis appuyez sur Créer.

Après avoir créé votre application, vous arriverez sur la page Informations générales des paramètres de l'application, où vous pourrez mettre à jour des informations de base sur votre application, comme sa description et son icône. Vous verrez également l'ID de l'application et l'URL du point de terminaison des interactions, que nous utiliserons un peu plus loin dans ce guide.

### Récupération de vos informations d'identification[

](https://discord.com/developers/docs/quick-start/getting-started#fetching-your-credentials)

Nous allons devoir configurer et récupérer quelques valeurs sensibles pour votre application, comme son token et son ID.

Votre jeton est utilisé pour autoriser les demandes d'API et porter les permissions de votre application, il est donc très sensible. Veillez à ne jamais partager votre jeton ni à l'enregistrer dans un quelconque système de contrôle de version.

De retour dans le dossier de votre projet, renommez le fichier `.env.sample` en `.env`. C'est là que nous allons stocker toutes les informations d'identification de votre application.

Nous aurons besoin de trois valeurs provenant des paramètres de votre application pour votre fichier `.env` :

- Sur la [page d'informations générales] (https://discord.com/developers/applications/select/information), copiez la valeur de l'ID de l'application. Dans `.env`, remplacez `<Votre_APP_ID>` par l'ID que vous avez copié.
- De retour sur la [page d'informations générales] (https://discord.com/developers/applications/select/information), copiez la valeur de Public Key, qui est utilisée pour s'assurer que les requêtes HTTP proviennent bien de Discord. Dans `.env`, remplacez `<Votre_Clef_Publique>` par la valeur que vous avez copiée.
- Sur la [page Bot](https://discord.com/developers/applications/select/bot) sous Token, cliquez sur "Reset Token" pour générer un nouveau bot token. Dans `.env`, remplacez `<Votre_BOT_TOKEN>` par votre nouveau token.

Vous ne pourrez plus voir votre token à moins de le régénérer, alors assurez-vous de le garder en lieu sûr (comme dans un gestionnaire de mot de passe).

Maintenant que vous avez les informations d'identification dont vous avez besoin, configurons l'utilisateur du bot et les paramètres d'installation.

### Configuration de votre bot[

](https://discord.com/developers/docs/quick-start/getting-started#configuring-your-bot)

Les applications nouvellement créées ont un utilisateur bot activé par défaut. Les utilisateurs de robots permettent à votre application d'apparaître et de se comporter comme les autres membres du serveur lorsqu'elle est [installée sur un serveur](https://discord.com/developers/docs/quick-start/overview-of-apps#where-are-apps-installed).

Dans la barre latérale gauche des paramètres de votre application, il y a une [page Bot](https://discord.com/developers/applications/select/bot) (où nous avons récupéré le jeton). Sur cette page, vous pouvez également configurer des paramètres tels que ses [intentions privilégiées](https://discord.com/developers/docs/events/gateway#privileged-intents) ou s'il peut être installé par d'autres utilisateurs.

Qu'est-ce qu'une intention ?

Introduction aux intentions standard et privilégiées

Pour l'instant, nous n'avons pas besoin de configurer quoi que ce soit d'autre ici, mais vous pourriez en avoir besoin à l'avenir en fonction du cas d'utilisation de votre application. Allons-y et préparons notre application pour l'installation.

### Choix des contextes d'installation[

](https://discord.com/developers/docs/quick-start/getting-started#choosing-installation-contexts)

Nous allons maintenant choisir où votre application peut être installée dans Discord, ce qui est déterminé par les [contextes d'installation](https://discord.com/developers/docs/resources/application#installation-context) que votre application prend en charge.

Que sont les contextes d'installation ?

Aperçu des endroits où les applications peuvent être installées

Cliquez sur [Installation](https://discord.com/developers/applications/select/installation) dans la barre latérale gauche, puis, sous Contextes d'installation, assurez-vous que les options "Installation par l'utilisateur" et "Installation par la guilde" sont sélectionnées.

Certaines applications peuvent ne prendre en charge qu'un seul contexte d'installation - par exemple, une application de modération peut ne prendre en charge qu'un contexte de serveur. Cependant, par défaut, nous recommandons de prendre en charge les deux contextes d'installation. Pour obtenir des informations détaillées sur la prise en charge des applications installées par l'utilisateur, vous pouvez consulter le [tutoriel sur les applications installables par l'utilisateur] (https://discord.com/developers/docs/tutorials/developing-a-user-installable-app).

### Mise en place d'un lien d'installation[

](https://discord.com/developers/docs/quick-start/getting-started#setting-up-an-install-link)

Les [liens d'installation](https://discord.com/developers/docs/resources/application#install-links) permettent aux utilisateurs d'installer facilement votre application dans Discord. Nous allons configurer le [Lien fourni par Discord](https://discord.com/developers/docs/resources/application#discord-provided-link) par défaut, mais vous pouvez en savoir plus sur les différents types de liens d'installation dans la [Documentation de l'application](https://discord.com/developers/docs/resources/application#types-of-install-links).

Sur la [page d'installation](https://discord.com/developers/applications/select/installation), allez dans la section Lien d'installation et sélectionnez "Discord Provided Link" si ce n'est pas déjà fait.

Lorsque vous sélectionnez Discorded Provided Link, une nouvelle section Default Install Settings (Paramètres d'installation par défaut) apparaît, que nous allons configurer par la suite.

### Ajout de champs d'application et de permissions pour les robots[

](https://discord.com/developers/docs/quick-start/getting-started#adding-scopes-and-bot-permissions)

Les applications ont besoin de l'approbation des utilisateurs qui les installent pour effectuer des actions dans Discord (comme la création d'une commande slash ou l'obtention d'une liste des membres du serveur). Ajoutons des scopes et des permissions avant d'installer l'application.

Que sont les champs d'application et les autorisations ?

Introduction aux champs d'application et aux autorisations des robots

Sur la [page d'installation] (https://discord.com/developers/applications/select/installation), dans la section Paramètres d'installation par défaut :

- Pour l'installation par l'utilisateur, ajoutez l'étendue `applications.commands`.
- Pour l'installation par la Guilde, ajoutez l'étendue `applications.commands` et l'étendue `bot`. Lorsque vous sélectionnez `bot`, un nouveau menu de permissions apparaît pour sélectionner les permissions de l'utilisateur du bot. Sélectionnez toutes les permissions que vous souhaitez pour votre application - pour l'instant, je vais juste sélectionner `Envoyer des Messages`.

![Paramètres d'installation par défaut](https://discord.com/assets/583fdb9654baaf4f.webp)

Voir une liste de tous les [OAuth2 scopes](https://discord.com/developers/docs/topics/oauth2#shared-resources-oauth2-scopes), ou en savoir plus sur les [permissions](https://discord.com/developers/docs/topics/permissions) dans la documentation.

### Installer votre application[

](https://discord.com/developers/docs/quick-start/getting-started#installing-your-app)

Lorsque vous développez des applications, vous devez les créer et les tester sur votre compte utilisateur (pour les applications installables par l'utilisateur) et sur un serveur qui n'est pas activement utilisé par d'autres (pour les applications installables sur le serveur). Si vous n'avez pas encore votre propre serveur, vous pouvez [en créer un gratuitement](https://support.discord.com/hc/en-us/articles/204849977-How-do-I-create-a-server-).

Une fois que vous avez ajouté des champs d'application, copiez l'URL de la section Lien d'installation.

Comme notre application supporte les deux contextes d'installation, nous allons installer votre nouvelle application à la fois sur un serveur de test et sur votre compte utilisateur afin de pouvoir tester les deux [contextes d'installation](https://discord.com/developers/docs/resources/application#installation-context).

###### Installer sur le serveur[

] (https://discord.com/developers/docs/quick-start/getting-started#installing-your-app-install-to-server)

Pour installer votre application sur votre serveur de test, copiez le lien d'installation par défaut de votre application à partir de la page d'installation. Collez le lien dans votre navigateur et appuyez sur la touche "Entrée", puis sélectionnez "Ajouter au serveur" dans l'invite d'installation.

Sélectionnez votre serveur de test et suivez les instructions d'installation. Une fois votre application ajoutée à votre serveur de test, vous devriez la voir apparaître dans la liste des membres.

###### Installer sur le compte de l'utilisateur[

](https://discord.com/developers/docs/quick-start/getting-started#installing-your-app-install-to-user-account)

Ensuite, installez votre application sur votre compte utilisateur. Collez le même lien d'installation dans votre navigateur et appuyez sur Entrée. Cette fois, sélectionnez "Ajouter à mes applications" dans l'invite d'installation.

Suivez l'invite d'installation pour installer votre application sur votre compte utilisateur. Une fois l'application installée, vous pouvez ouvrir un DM avec elle.

## Étape 2 : Exécution de votre application[

](https://discord.com/developers/docs/quick-start/getting-started#step-2-running-your-app)

Une fois votre application configurée et installée sur votre serveur et compte de test, jetons un coup d'oeil au code.

Pour simplifier le développement, l'application utilise [discord-interactions](https://github.com/discord/discord-interactions-js), qui fournit des types et des fonctions d'aide. Si vous préférez utiliser d'autres langages ou bibliothèques, consultez la documentation [Community Resources](https://discord.com/developers/docs/developer-tools/community-resources).

### Installation des commandes slash[

](https://discord.com/developers/docs/quick-start/getting-started#installing-slash-commands)

Pour installer les commandes slash, l'application utilise [`node-fetch`](https://github.com/node-fetch/node-fetch). Vous pouvez voir l'implémentation de l'installation dans `utils.js` dans la fonction `DiscordRequest()`.

Le projet contient un script `register` que vous pouvez utiliser pour installer les commandes dans `ALL_COMMANDS`, qui est défini au bas de `commands.js`. Il installe les commandes en tant que commandes globales en appelant le point de terminaison de l'API HTTP [`PUT /applications/<APP_ID>/commandes`](https://discord.com/developers/docs/interactions/application-commands#bulk-overwrite-global-application-commands).

## Étape 3 : Gérer l'interactivité[

](https://discord.com/developers/docs/quick-start/getting-started#step-3-handling-interactivity)

Pour permettre à votre application de recevoir la commande slash et d'autres demandes d'interaction, Discord a besoin d'une URL publique pour les envoyer. Cette URL peut être configurée dans les paramètres de votre application comme Interaction Endpoint URL.

### Configurez un point de terminaison public[

](https://discord.com/developers/docs/quick-start/getting-started#set-up-a-public-endpoint)

Pour mettre en place un point d'accès public, nous allons démarrer notre application qui exécute un serveur [Express](https://expressjs.com/), puis utiliser [ngrok](https://ngrok.com/) pour exposer notre serveur publiquement.

Tout d'abord, allez dans le dossier de votre projet et exécutez ce qui suit pour démarrer votre application :

Copiez

```
npm run start
```

Il devrait y avoir une sortie indiquant que votre application tourne sur le port `3000`. Dans les coulisses, notre application est prête à gérer les interactions avec Discord, ce qui inclut la vérification des en-têtes des requêtes de sécurité et la réponse aux requêtes `PING`. Nous passons sur beaucoup de détails dans ce tutoriel, mais les détails sur la préparation des applications pour les interactions se trouvent dans la documentation [Interactions Overview](https://discord.com/developers/docs/interactions/overview#preparing-for-interactions).

Par défaut, le serveur écoutera les requêtes envoyées au port 3000, mais si vous voulez changer le port, vous pouvez spécifier une variable `PORT` dans votre fichier `.env`.

Ensuite, nous allons démarrer notre tunnel ngrok. Si vous n'avez pas ngrok installé localement, vous pouvez l'installer en suivant les instructions de la [page de téléchargement de ngrok] (https://ngrok.com/download).

Une fois ngrok installé, ouvrez un nouveau terminal et créez un point de terminaison public qui transmettra les requêtes à votre serveur Express :

Copiez

```
ngrok http 3000
```

Vous devriez voir votre connexion ouverte avec une sortie similaire à la suivante :

Copiez

```

```

Nous utiliserons l'URL de transfert comme URL publiquement accessible où Discord enverra les demandes d'interaction dans l'étape suivante.

### Ajout d'un point final d'interaction URL[

](https://discord.com/developers/docs/quick-start/getting-started#adding-an-interaction-endpoint-url)

Allez dans les [paramètres de l'application](https://discord.com/developers/applications) et sur la [page d'informations générales](https://discord.com/developers/applications/select/information) sous Interaction Endpoint URL, collez votre nouvelle URL de redirection ngrok et ajoutez `/interactions`.

La vérification est gérée automatiquement par l'application d'exemple de deux manières :

- Elle utilise la `PUBLIC_KEY` et [le paquet discord-interactions](https://github.com/discord/discord-interactions-js#usage) avec une fonction wrapper (importée de `utils.js`) qui la rend conforme à [l'interface `verify` d'Express](http://expressjs.com/en/5x/api.html#express.json). Ceci est exécuté sur chaque requête entrante dans votre application.
- Il répond aux requêtes `PING` entrantes.

Vous pouvez en apprendre plus sur la préparation de votre application pour recevoir des interactions dans [la documentation sur les interactions](https://discord.com/developers/docs/interactions/overview#preparing-for-interactions).

## Étape 4 : Ajout de composants de message[

](https://discord.com/developers/docs/quick-start/getting-started#step-4-adding-message-components)

La commande `/challenge` sera le moyen de lancer notre jeu de type pierre-papier-ciseaux. Lorsque la commande est déclenchée, l'application envoie des composants de message au canal, qui guident les utilisateurs pour qu'ils terminent le jeu.

### Ajouter une commande avec des options[

](https://discord.com/developers/docs/quick-start/getting-started#adding-a-command-with-options)

La commande `/challenge`, appelée `CHALLENGE_COMMAND` dans `commands.js`, possède un tableau d'options. Dans notre application, les options sont des objets représentant les différentes choses qu'un utilisateur peut sélectionner en jouant à pierre-papier-ciseaux, générés en utilisant les clés de `RPSChoices` dans `game.js`.

Vous pouvez en savoir plus sur les options de commande et leur structure [dans la documentation](https://discord.com/developers/docs/interactions/application-commands#application-command-object-application-command-option-structure).

Bien que ce guide n'aborde pas beaucoup le fichier `game.js`, n'hésitez pas à y jeter un coup d'oeil et à changer les commandes ou les options dans les commandes.

Gérer l'interaction avec les commandes

Code pour gérer la commande challenge et répondre avec un message contenant un bouton

Pour gérer la commande `/challenge`, ajoutez le code suivant après le bloc `if name === "test"` if :

Copiez

``javascript
// Commande "challenge
if (name === 'challenge' && id) {
  // Contexte d'interaction
  const context = req.body.context ;
  // L'ID de l'utilisateur se trouve dans le champ utilisateur pour les (G)DM, et dans le champ membre pour les serveurs
  const userId = context === 0 ? req.body.member.user.id : req.body.user.id ;
  // Choix de l'objet de l'utilisateur
  const objectName = req.body.data.options[0].value ;

  // Créez un jeu actif en utilisant l'ID du message comme ID du jeu
  activeGames[id] = {
    id : userId,
    objectName,
  } ;

  return res.send({
    type : InteractionResponseType.CHANNEL_MESSAGE_WITH_SOURCE,
    data : {
      flags : InteractionResponseFlags.IS_COMPONENTS_V2,
      composants : [
        {
          type : MessageComponentTypes.TEXT_DISPLAY,
          // Récupère un emoji aléatoire à envoyer à partir d'une fonction d'aide
          content : `Rock papers scissors challenge from <@${userId}>`,
        },
        {
          type : MessageComponentTypes.ACTION_ROW,
          composants : [
            {
              type : MessageComponentTypes.BUTTON,
              // Ajoutez l'ID du jeu pour l'utiliser plus tard
              custom_id : `accept_button_${req.body.id}`,
              label : 'Accept',
              style : ButtonStyleTypes.PRIMARY,
            },
          ],
        },
      ],
    },
  }) ;
}
```

Si vous n'êtes pas sûr de l'endroit où coller le code, vous pouvez voir le code complet dans `examples/app.js`.

Le code ci-dessus fait plusieurs choses :

1. Il analyse le corps de la requête pour obtenir l'ID de l'utilisateur qui a déclenché la commande slash (`userId`), et l'option (choix d'objet) qu'il a sélectionnée (`objectName`). Si l'interaction est exécutée dans un serveur (`context === 0`), l'ID de l'utilisateur sera imbriqué dans l'objet `member`. S'il s'agit d'un DM ou d'un Group DM, il sera dans l'objet `user`.
2. Ajoute un nouveau jeu à l'objet `activeGames` en utilisant l'ID d'interaction. Le jeu actif enregistre le `userId` et le `objectName`.
3. Renvoie un message au canal avec un bouton ayant un `custom_id` de `accept_button_<SOME_ID>`.

L'exemple de code utilise un objet comme stockage en mémoire, mais pour les applications de production, vous devriez utiliser une base de données.

Lorsque vous envoyez un message avec [message components] (https://discord.com/developers/docs/components/reference), les charges utiles individuelles sont ajoutées à un tableau `components`. Les composants actionnables (comme les boutons) doivent se trouver à l'intérieur d'une [action row](https://discord.com/developers/docs/components/reference#action-row), comme vous pouvez le voir dans l'exemple de code.

Notez le `custom_id` unique envoyé avec les composants de message, dans ce cas `accept_button_` avec l'ID du jeu actif en annexe. Un `custom_id` peut être utilisé pour gérer les requêtes que Discord vous envoie lorsque quelqu'un interagit avec le composant, ce que vous verrez dans un instant.

Maintenant, lorsque vous lancez la commande `/challenge` et choisissez une option, votre application enverra un message avec un bouton Accept. Ajoutons du code pour gérer l'appui sur le bouton.

Gérer les interactions avec les boutons

Code pour gérer les clics sur les boutons et répondre avec un message éphémère

Lorsque les utilisateurs interagissent avec un composant de message, Discord envoie une requête avec un [type d'interaction](https://discord.com/developers/docs/interactions/receiving-and-responding#interaction-object-interaction-type) de `3` (ou la valeur `MESSAGE_COMPONENT` si vous utilisez `discord-interactions`).

Pour mettre en place un gestionnaire pour le bouton, nous allons vérifier le `type` d'interaction, suivi de la correspondance avec le `custom_id`.

Collez le code suivant sous le gestionnaire de type pour `APPLICATION_COMMAND`s :

Copiez

``javascript
if (type === InteractionType.MESSAGE_COMPONENT) {
  // le custom_id est défini dans le payload lors de l'envoi du composant du message
  const componentId = data.custom_id ;

  if (componentId.startsWith('accept_button_')) {
    // récupère l'identifiant du jeu associé
    const gameId = componentId.replace('accept_button_', '') ;
    // Supprimez le message avec le jeton dans le corps de la requête
    const endpoint = `webhooks/${process.env.APP_ID}/${req.body.token}/messages/${req.body.message.id}` ;
    try {
      await res.send({
        type : InteractionResponseType.CHANNEL_MESSAGE_WITH_SOURCE,
        data : {
          // Indique qu'il s'agit d'un message éphémère
          flags : InteractionResponseFlags.EPHEMERAL | InteractionResponseFlags.IS_COMPONENTS_V2,
          composants : [
            {
              type : MessageComponentTypes.TEXT_DISPLAY,
              content : 'Quel est l'objet de votre choix ?',
            },
            {
              type : MessageComponentTypes.ACTION_ROW,
              composants : [
                {
                  type : MessageComponentTypes.STRING_SELECT,
                  // Ajoutez l'ID du jeu
                  custom_id : `select_choice_${gameId}`,
                  options : getShuffledOptions(),
                },
              ],
            },
          ],
        },
      }) ;
      // Supprimez le message précédent
      await DiscordRequest(endpoint, { method : 'DELETE' }) ;
    } catch (err) {
      console.error('Error sending message:', err) ;
    }
  }
  return ;
}
```

Le code ci-dessus :

1. Vérifie qu'il y a un `custom_id` qui correspond à ce que nous avons envoyé à l'origine (dans ce cas, il commence par `accept_button_`). L'ID personnalisé contient également l'ID du jeu actif, donc nous le stockons dans `gameID`.
2. (https://discord.com/developers/docs/interactions/receiving-and-responding#delete-original-interaction-response) appeler un webhook en utilisant `node-fetch` et en passant le `token` d'interaction unique dans le corps de la requête. Ceci est fait pour nettoyer le canal, et pour que les autres utilisateurs ne puissent pas cliquer sur le bouton.
3. Répond à la requête en envoyant un message qui contient un menu de sélection avec les choix d'objets pour le jeu. Le message devrait être assez similaire au précédent, à l'exception du tableau `options` et de `flags : 64`, [qui indique que le message est éphémère](https://discord.com/developers/docs/interactions/receiving-and-responding#create-followup-message).

Le tableau `options` est rempli en utilisant la méthode `getShuffledOptions()` dans `game.js`, qui manipule les valeurs `RPSChoices` pour se conformer à la forme des [options de sélection de chaîne](https://discord.com/developers/docs/components/reference#string-select-select-option-structure).

Gestion des interactions avec le menu de sélection

Code pour répondre aux interactions du menu de sélection et mettre à jour l'état du jeu

La dernière chose à ajouter est du code pour gérer les interactions avec le menu de sélection et pour envoyer le résultat du jeu au canal.

Étant donné que les menus de sélection ne sont qu'un autre composant de message, le code pour gérer leurs interactions sera presque identique à celui des boutons.

Modifiez le code ci-dessus pour gérer le menu de sélection :

Copiez

```javascript
if (type === InteractionType.MESSAGE_COMPONENT) {
  // le custom_id est défini dans le payload lors de l'envoi du composant du message
  const componentId = data.custom_id ;

  if (componentId.startsWith('accept_button_')) {
    // récupère l'identifiant du jeu associé
    const gameId = componentId.replace('accept_button_', '') ;
    // Supprimez le message avec le jeton dans le corps de la requête
    const endpoint = `webhooks/${process.env.APP_ID}/${req.body.token}/messages/${req.body.message.id}` ;
    try {
      await res.send({
        type : InteractionResponseType.CHANNEL_MESSAGE_WITH_SOURCE,
        data : {
          // Indique qu'il s'agit d'un message éphémère
          flags : InteractionResponseFlags.EPHEMERAL | InteractionResponseFlags.IS_COMPONENTS_V2,
          composants : [
            {
              type : MessageComponentTypes.TEXT_DISPLAY,
              content : 'Quel est l'objet de votre choix ?',
            },
            {
              type : MessageComponentTypes.ACTION_ROW,
              composants : [
                {
                  type : MessageComponentTypes.STRING_SELECT,
                  // Ajoutez l'ID du jeu
                  custom_id : `select_choice_${gameId}`,
                  options : getShuffledOptions(),
                },
              ],
            },
          ],
        },
      }) ;
      // Supprimez le message précédent
      await DiscordRequest(endpoint, { method : 'DELETE' }) ;
    } catch (err) {
      console.error('Error sending message:', err) ;
    }
  } else if (componentId.startsWith('select_choice_')) {
    // récupère l'identifiant du jeu associé
    const gameId = componentId.replace('select_choice_', '') ;

    if (activeGames[gameId]) {
      // Contexte d'interaction
      const context = req.body.context ;
      // Obtenez l'ID de l'utilisateur et le choix de l'objet pour l'utilisateur qui a répondu
      // L'identifiant de l'utilisateur se trouve dans le champ utilisateur pour les (G)DM, et dans le champ membre pour les serveurs.
      const userId = context === 0 ? req.body.member.user.id : req.body.user.id ;
      const objectName = data.values[0] ;
      // Calculez le résultat de la fonction d'aide
      const resultStr = getResult(activeGames[gameId], {
        id : userId,
        objectName,
      }) ;

      // Supprimez le jeu de la mémoire
      delete activeGames[gameId] ;
      // Mise à jour du message avec le jeton dans le corps de la requête
      const endpoint = `webhooks/${process.env.APP_ID}/${req.body.token}/messages/${req.body.message.id}` ;

      try {
        // Envoi des résultats
        await res.send({
          type : InteractionResponseType.CHANNEL_MESSAGE_WITH_SOURCE,
          data : {
            flags : InteractionResponseFlags.IS_COMPONENTS_V2,
            composants : [
              {
                type : MessageComponentTypes.TEXT_DISPLAY,
                content : resultStr
              }
            ]
            },
        }) ;
        // Mise à jour du message éphémère
        await DiscordRequest(endpoint, {
          method : 'PATCH',
          body : {
            composants : [
              {
                type : MessageComponentTypes.TEXT_DISPLAY,
                content : 'Bon choix ' + getRandomEmoji()
              }
            ],
          },
        }) ;
      } catch (err) {
        console.error('Error sending message:', err) ;
      }
    }
  }

  retour ;
}
```

Comme le code précédent, le code ci-dessus récupère l'identifiant de l'utilisateur et sa sélection d'objets à partir de la demande d'interaction.

Ces informations, ainsi que l'ID de l'utilisateur original et la sélection de l'objet `activeGames`, sont passées à la fonction `getResult()`. `getResult()` détermine le gagnant, puis construit une chaîne lisible à renvoyer au canal.

Nous appelons également un autre webhook, cette fois pour [mettre à jour le message éphémère de suivi](https://discord.com/developers/docs/interactions/receiving-and-responding#edit-followup-message) puisqu'il ne peut pas être supprimé.

Enfin, les résultats sont envoyés dans le canal en utilisant le type de réponse d'interaction `CHANNEL_MESSAGE_WITH_SOURCE`.
